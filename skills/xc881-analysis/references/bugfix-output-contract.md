# Output

```text
xc881 诊断: <一句话主题>
结论:
背景:
依据:
修复:
验证:
需要注意:
下一步:
```

`结论`: 根因一句话 + 置信度（confirmed | unconfirmed + 缺的检查）。
`背景`: 现象和环境。`依据`: 分点证据，可带文件锚点。
`修复`: 最小修复分点。`验证`: 最小复现 + 怎么确认修好；只是计划，直到
Coding 返回实际运行结果才算验证。

安全问题附加：

```text
严重程度: P0-P3
编号: CVE/GHSA/OSV/CWE/OWASP
影响范围:
可利用性:
缓解措施:
```

Tracker 附加沿用 Requirement 的 `事项状态 / 给开发的说明 / 平台操作`；bug 字段：
`现状 / 期望 / 复现 / 验收 / 验证`。tracker 标签/评论走 Requirement 分支，
Bugfix 分支只提供证据、根因、修复和验证计划。

仓库证据：简单精确局部读取自己做，复杂/tracked 只读问题交给 Coding，随后回到
Bugfix。只有请求或委派了实现且修复有依据时，`下一步` 才把根因、证据锚点、有界
修复、非回归约束和精确验证步骤交给 Coding；仅诊断写 `下一步: 仅诊断` 或写明
缺的证据。
